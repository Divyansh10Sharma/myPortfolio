S-04

Step reconciliation

A sensor that only counts since boot, corrected against the cloud every fifty steps.

Read the detail

A native Android module reading the hardware step sensor, which reports a cumulative count since boot rather than steps today. It derives a boot-time offset against Google Fit and re-derives it every fifty steps when drift is detected — reconciling a fast, offline, locally-drifting sensor against a slower cloud-authoritative total. Also fixes a HealthKit day-boundary bug that mis-attributed steps in positive UTC offsets.

Stack Java · Google Fit · HealthKit · React Native

S-05

Payment reliability

Three independent layers, because a webhook is not a promise.

Read the detail

Three independent recovery layers against Razorpay: an HMAC-SHA256 webhook with timing-safe verification, a fifteen-minute poller re-checking pending payments, and a nightly subscription reconciliation against Razorpay as source of truth. Every save path is independently idempotent, because the webhook, the poller and the client can all fire for the same payment.

Stack Flask · Razorpay · PostgreSQL

S-06

Firestore to PostgreSQL migration

Reading from both databases in one request until the old one can be switched off.

Read the detail

An incremental migration flattening four-level nested collections into normalised tables with idempotent writes. Uses a strangler-fig read-merge: queries both stores in a single request, deduplicates by composite key, and tags each row with its data origin for debuggability — so reads stay correct throughout the transition.

Stack PostgreSQL · Firestore · Python
